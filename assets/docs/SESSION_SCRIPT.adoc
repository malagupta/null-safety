== Act 1 — Why: null is invisible in the type system (~3 min)

*Show:* `01_WhyNullExists.adoc` → `02_TypicalNPEs.adoc`

*Say:*

* "Three reasons null exists: optional attribute, lazy load, GC marker. All three are legitimate. None of them show up in the type."
* "Tony Hoare: 'I call it my billion-dollar mistake.' He invented null in 1965 to make it easy. The compiler accepted it. Developers paid for it."
* "Three patterns that hurt us: stack traces don't say _which_ link in a chain was null; method signatures don't say whether they return null; defensive null checks added now hide real bugs introduced later."

== Act 3 — Fix 2: Optional — put absence in the type (~4 min)

*Show:* `03_Solutions.adoc` — Optional section

*Type `findByName` above `act3_Optional()`:*

[source,java]
----
static Optional<Coffee> findByName(String name) {
    return Optional.ofNullable(MENU.get(name));
}
----

*Say:* "The return type is now the contract. `Optional<Coffee>` forces every caller to handle absence. The AI can see this. The compiler can see this."

*Inside `act3_Optional()`, type:*

[source,java]
----
String found = findByName("espresso")
        .map(Coffee::name)
        .map(String::toUpperCase)
        .orElse("Not found");
System.out.println("Found   : " + found);

String missing = findByName("coldpresso")
        .map(Coffee::name)
        .orElse("Not on menu — try our cold brew");
System.out.println("Missing : " + missing);

// orElseThrow: absence here is a bug, not a valid state
findByName("coldpresso")
        .orElseThrow(() ->
                new IllegalStateException("coldpresso must be configured — check setup"));
----

*Run it.*

----
── Act 3: Optional ──
Found   : ESPRESSO
Missing : Not on menu — try our cold brew
Exception in thread "main" java.lang.IllegalStateException: coldpresso must be configured — check setup
----

*Say:*

* "`.map()` is a no-op if empty — no null checks in the chain."
* "`.orElse()` is the default. `.orElseThrow()` is the signal that absence is a defect."
* **Anti-pattern to call out:** "`.get()` without a check is the same as a null dereference, just wrapped in an Optional. Never use it."

[TIP]
Optional is for *return types* only. Not fields. Not constructor parameters. Not collections.

== Act 4 — Fix 3 + 4: Records (fail fast) + JSpecify (encoded contract) (~7 min)

=== Part A — Records

*Show:* `04_ModernJavaSolutions1.adoc`

*Ask the audience:* "Where's the earliest moment we can reject a null?" (Answer: at construction.)

*Type `CoffeeOrder` above `act4_RecordsAndJSpecify()`:*

[source,java]
----
record CoffeeOrder(String customerName, Coffee coffee, int shots) {
    CoffeeOrder {
        Objects.requireNonNull(customerName);
        Objects.requireNonNull(coffee);
        if (shots < 1 || shots > 4) throw new IllegalArgumentException();
    }
}
----

*Inside `act4_RecordsAndJSpecify()`, type:*

[source,java]
----
Coffee espresso = new Coffee("Espresso", "Ethiopian", "Grind fine.");
CoffeeOrder good = new CoffeeOrder("Alice", espresso, 2);
System.out.println("Good : " + good.customerName() + " / " + good.coffee().name());

try {
    CoffeeOrder bad = new CoffeeOrder("Bob", null, 1);
} catch (NullPointerException e) {
    System.out.println("Null rejected at construction — not 20 frames later");
}
----

*Run it.*

----
── Act 4: Records + JSpecify ──
Good : Alice / Espresso
Null rejected at construction — not 20 frames later
----

*Say:* "Records are effectively final — the compact constructor runs before the object exists. Null never gets in. The NPE stack trace now points directly at the problem."

=== Part B — JSpecify

*Show:* `03_Solutions.adoc` — JSpecify section

*Add `@NullMarked` above the class declaration:*

[source,java]
----
@NullMarked
public class LiveCodingSession {
----

*Say:* "This one annotation changes the default for every field, parameter, and return type in this class: *silence means non-null*. `@Nullable` breaks that silence deliberately."

*Type the two annotated records:*

[source,java]
----
record CoffeeV2(
        String name,                               // non-null — @NullMarked default
        String origin,                             // non-null — @NullMarked default
        @Nullable String brewingInstructions       // null is valid — annotation says so
) {}

record OrderV2(
        String customerName,                       // non-null — @NullMarked default
        @Nullable CoffeeV2 coffee                  // null is valid — customer may not have chosen
) {}
----

*Add to `act4_RecordsAndJSpecify()`:*

[source,java]
----
OrderV2 pending = new OrderV2("Jonathan", null);  // allowed — @Nullable says so
System.out.println("Pending : " + pending.customerName() + " / coffee=" + pending.coffee());

// NullAway (build plugin) would reject this as a COMPILE ERROR:
// String name = pending.coffee().name();  // dereference @Nullable without null check

if (pending.coffee() != null) {
    System.out.println("Coffee  : " + pending.coffee().name());
} else {
    System.out.println("No coffee chosen yet");
}
----

*Run it.*

----
Pending : Jonathan / coffee=null
No coffee chosen yet
----

*Say:*

* "Without NullAway these are documentation — enforced by convention."
* "With NullAway they become *compile errors*, not runtime surprises."
* "Reference `JSpecifyDemo.java` for the full picture: return types, parameters, chained access, `@NullUnmarked` for legacy bridges."

=== Step A — Live-edit CLAUDE.md

*Switch to `CLAUDE.md`. Scroll to the bottom. Type this block live:*

[source,markdown]
----
## Null Safety

All new code must follow these conventions.
They are enforced by `@NullMarked` + NullAway at build time.

- Annotate every new class with `@NullMarked` (org.jspecify)
- Mark fields, parameters, and return types that may be null with `@Nullable`
- Public methods must never return `null` — use `Optional<T>` instead
- Reject null constructor arguments with `Objects.requireNonNull()` in compact constructors
- Wrap any third-party or legacy API that returns null with `Optional.ofNullable()` at the boundary
- Use `@NullUnmarked` only on legacy adapter classes, never on new code
- Never call `.get()` on an Optional — use `.orElse()`, `.orElseThrow()`, or `.ifPresentOrElse()`
----

*Save `CLAUDE.md`.*

== Wrap-up — The decision guide (~2 min, no code)

*Show:* `08_SolutionDecisions.adoc`

[cols="<2,<3"]
|===
| Question | Answer

| Is null a valid domain state, or a bug?
| Valid → `@Nullable` + `Optional` return +
  Bug   → `Objects.requireNonNull()` at construction

| Do you control the code at this boundary?
| Yes → `@NullMarked` + `@Nullable` throughout +
  No  → `Optional.ofNullable()` adapter wraps the edge

| What Java version are you on?
| 8–11  → Optional + requireNonNull + JSpecify + NullAway +
  16+   → add Records +
  17+   → add Sealed classes +
  21+   → add switch null case and pattern matching
|===

*Show:* `09_TheFuture.adoc`

*Say:* "Project Valhalla proposes `String!` — a non-null type built into the language. Until Valhalla ships, JSpecify + NullAway + a well-kept `CLAUDE.md` is as close as Java gets to compiler-enforced null safety."
